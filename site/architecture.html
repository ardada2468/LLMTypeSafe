01

One request, end to end

A signature class records its fields on the constructor at decoration time, so getInputFields() and getOutputFields() work without ever instantiating it. Predict.forward() hands the signature to an adapter, which reads those fields three separate times: once to write the chat messages, once to build a JSON Schema for providers that can constrain decoding, and once to build the zod schema that every reply must pass.

The fork in the middle is where the default adapter is chosen — JSONAdapter or ChatAdapter, unless you pass one. They rejoin at the same gate, so a model that answers in prose where you declared a number fails identically whichever route it took.

02

Packages and the provider seam

@ts-dspy/core depends on zod and nothing else — no vendor SDK. Each provider package pulls in its own official SDK and extends BaseLM, which already owns usage accounting, generate() delegation, and a prompt-based generateStructured() fallback. A provider implements two methods: chat() and getCapabilities().

Modules never name a vendor. They resolve an ILanguageModel at call time — the call's options.lm, the module's own, the active settings.context scope, then configure(). @ts-dspy/ai-sdk is a fourth provider of the same kind, wrapping any Vercel AI SDK model; @ts-dspy/mcp and @ts-dspy/otel sit beside core rather than beneath it, as tools and as a callback.

03

What each module adds

Every module extends Module, which resolves the language model at call time and supplies the forward() contract, composition (namedPredictors(), deepCopy()) and persistence (dumpState(), save()). call() and __call__() are aliases for it.

04

The ReAct loop

ReAct is the module whose control flow is a cycle rather than a line. Each step is a prediction by the react predictor over the signature's inputs plus the trajectory so far, producing next_thought, next_tool_name and next_tool_args. The tool's observation is appended to the trajectory — thought_0, tool_name_0, tool_args_0, observation_0, … — and the step repeats.

The loop ends when the model chooses the reserved tool finish, when maxSteps is spent, or when a step cannot be parsed. In every case an extract ChainOfThought reads the inputs and the whole trajectory and produces the signature's outputs. A tool call identical to one already made gets an observation telling the model to move on instead of being executed again.

Design constraint

Coercion is deliberately lenient and validation is deliberately loud. "42" satisfies a number field, and so does "1,200" and "87%" — commas and a trailing percent are stripped before the check. But "about forty" throws a ValidationError naming the field rather than handing back a string where the type says number. Versions before 0.5.0 returned the raw string on coercion failure, which is exactly the lie the runtime check exists to prevent.
